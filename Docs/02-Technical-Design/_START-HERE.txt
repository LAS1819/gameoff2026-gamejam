🎮 THE MVP: 8-STEP GAMEPLAY LOOP
───────────────────────────────────────────────────────────────────────────────

1. Start game
   Location: Vestibule
   Event: StaffKey appears (visible in Normal reality)

2. Pick up staff key
   Action: Click StaffKey
   Flag: HasStaffKey = true
   Result: Key disappears, added to inventory

3. Unlock front door with key
   Action: Click FrontDoor (requires staff_key)
   Flag: DoorOpened = true
   Result: Door opens, HallwayEntrance unlocked

4. Enter hallway
   Action: Click HallwayEntrance (requires DoorOpened)
   Event: Room transitions to Hallway
   Result: HallwayObstacle appears (visible in Normal reality)

5. Examine obstacle
   Action: Click HallwayObstacle
   Flag: RealityUnlocked = true
   Result: Unlock reality shift ability

6. Shift to alternate reality
   Action: Click ShiftTrigger
   Flag: ShiftPerformed = true
   Event: CurrentReality toggles (Normal ↔ OtherSide)
   Result: HallwayObstacle disappears (not visible in OtherSide)

7. Player can navigate
   Effect: Path forward is clear
   Result: Progression validated

8. Shift back (or return to vestibule)
   Action: Click ShiftTrigger again / Click VestibuleExit
   Result: Reality toggles back / Room transitions
           State preserved (no flags reset)

MVP Victory: Complete loop works without errors.


🏗️  ARCHITECTURE: 4 KEY PRINCIPLES
───────────────────────────────────────────────────────────────────────────────

1. DATA-DRIVEN
   Everything is configuration, not code
   → All puzzle logic lives in RoomData and InteractableData
   → Designers can modify content without programming

2. MANAGER-BASED
   Central runtime systems, persistent across scenes
   Bootstrap Scene → Systems
   └─ GameManager, RoomManager, InventoryManager
   └─ InteractionManager, RealityManager, EventManager
   └─ SaveManager, UIManager (stubs)
   → All marked with DontDestroyOnLoad

3. FLAG-DRIVEN
   Game state via boolean flags, not object queries
   Flags: HasStaffKey, DoorOpened, RealityUnlocked, ShiftPerformed
   → Progression is explicit and debuggable
   → Easy to save/load later

4. GENERIC SYSTEMS
   No room-specific code
   → All systems work for any room
   → Scales to 10+ rooms without changes
